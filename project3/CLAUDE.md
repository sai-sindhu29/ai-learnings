# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`project3` is an SAP Fiori application generated by SAP Fiori tools: List Report Page V2 template, UI5 1.114.9, `sap_horizon` theme, JavaScript (TypeScript disabled). It is backed by the OData V2 service `ZMS_CDS_SERBINDING` on `hilmar.sapvista.com:50000`, with main entity `ZMS_CDS_SALORDHDR`.

## Commands

Run from the project root. Run `npm install` first if `node_modules/` is missing.

- `npm start`: dev server against the live backend. Uses `ui5.yaml` and proxies `/sap` to the backend through the `S4H` destination.
- `npm run start-local`: uses `ui5-local.yaml`. A mock server answers the `ZMS_CDS_SERBINDING` path; other `/sap` paths still proxy to the backend.
- `npm run start-mock`: uses `ui5-mock.yaml`. Serves generated mock data from `localService/mainService/metadata.xml`, with no backend needed.
- `npm run build`: `ui5 build` into `dist/`.
- `npm run lint`: `eslint ./` with the `@sap-ux/eslint-plugin-fiori-tools` recommended rules. Silent output means no errors.
- `npm run deploy`: `fiori verify`. This is a verification step, not a deployment.

There is no test framework or test directory, so there is no test command and no way to run a single test.

## Architecture

- **Fiori Elements, no custom controllers or views.** `webapp/Component.js` only extends `sap/suite/ui/generic/template/lib/AppComponent` with `metadata.manifest: "json"`. Routing, page tree (`ListReport|ZMS_CDS_SALORDHDR` → `ObjectPage|ZMS_CDS_SALORDHDR`), table settings (GridTable, smart variant management), and filter settings are all in `webapp/manifest.json`. Change behavior there and in annotations rather than in JavaScript.
- **Annotations drive the UI.** Columns, facets, and field groups come from annotations, not from `manifest.json`. `mainService` loads two annotation sources, in this order:
  1. `localService/mainService/ZMS_CDS_SERBINDING_VAN.xml`, a local copy of the backend annotation document from the catalog service (`/sap/opu/odata/IWFND/CATALOGSERVICE;v=2/Annotations(TechnicalName='ZMS_CDS_SERBINDING_VAN',Version='0001')`).
  2. `annotations/annotation.xml`, the project's own file. It currently holds only vocabulary references and a reference to the backend `$metadata` for namespace `cds_zms_sd_salord`.
- **Data source.** `manifest.json` `sap.app.dataSources.mainService` is the default OData V2 model (`TwoWay` binding, inline count). Its metadata is the local copy `localService/mainService/metadata.xml`.
- **Three YAML configs repeat the same service wiring.** `ui5.yaml`, `ui5-local.yaml`, and `ui5-mock.yaml` each declare the `/sap` proxy and the `sap-fe-mockserver` service path, metadata, and annotation paths. `ui5-local.yaml` also lists framework libraries explicitly. When you change the service path or annotation locations, update all three.
- **Generator-owned metadata.** `sapux`, `sapuxLayer`, `sourceTemplate`, and `.appGenInfo.json` are written by SAP Fiori tools. Don't hand-edit them.
- **`ai-labs/` is a separate nested git repo** with its own copies of this app per learning day (e.g. `ai-labs/day-00/`, which has its own CLAUDE.md and a different layout). It is not built by the root scripts. Edit the root project unless the user names `ai-labs/`.
